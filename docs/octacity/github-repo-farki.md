# .github ile Octacity Docs arasındaki fark nedir?

Kısa ve net ayrım şudur:

> **`.github`**, Octacity'nin nasıl yönetildiğini ve işlediğini belirler.  
> **Octacity Docs**, topluluk üyelerinin daha kaliteli açık kaynak projeler inşa etmesine rehberlik eder.

Bu iki kaynak birbirinin alternatifi veya kopyası değildir; tamamen farklı sorumluluk alanlarına hizmet ederler.

## İki kaynağın karşılaştırması

| Kapsam | `octacity-org/.github` | Octacity Docs |
| :--- | :--- | :--- |
| **Amaç** | Yönetişim, kurumsal politikalar, şablonlar | Pratik rehberlik, yöntemler, tecrübe aktarımı |
| **Niteliği** | Bağlayıcı kural ve süreçler | Öneri, iyi pratikler, yol haritası |
| **Örnek İçerik** | Üyelik şartları, liderlik yetkileri, CoC metni | İyi PR nasıl açılır, fikri nasıl küçültürüm |
| **Dil** | Resmi, standart ve bağlayıcı | Samimi, doğrudan ve öğretici |

## Ne zaman hangisine bakmalıyım?

- **`.github` deposuna bakın:** Bir Octacity organizasyon kuralını, resmi katkı politikasını, ekip yapısını veya kurumsal şablonları öğrenmek istediğinizde.
- **Octacity Docs'a bakın:** "Bu projeyi nasıl başlatmalıyım?", "Issue'yu nasıl yazarsam anlaşılır olur?", "Ekipte teknik anlaşmazlık çıkarsa ne yapmalıyız?" gibi geliştirme süreçlerine dair pratik cevaplar aradığınızda.

## Neden kurallar dokümantasyona kopyalanmıyor?

Politikaları ve resmi süreçleri dokümantasyon içine kopyalamak iki farklı bilgi kaynağının zamanla birbirinden kopmasına (drift) yol açar. Bir kural güncellendiğinde iki yerin birden güncellenmesi zorlaşır. 

Bu nedenle Octacity Docs içerisinde resmi bir prosedür gerektiğinde doğrudan `.github` üzerindeki kanonik adrese link verilir.
